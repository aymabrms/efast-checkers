MULTI-YEAR AFS SUPPORT V1

IMPORTANT:
- Inspect the existing implementation first
- Keep this low-risk and low-credit
- Do NOT redesign the app
- Do NOT add OCR, NLP, ML, external APIs, or new dependencies

GOAL

Support AFS reports containing:

- current period only
- current period + 1 comparative year
- current period + 2 comparative years

Examples:

2025

2025 / 2024

2025 / 2024 / 2023

The prototype must not assume that every AFS has comparative figures.

--------------------------------------------------
1. IMPROVE UPLOAD / INTAKE YEAR INPUT
--------------------------------------------------

Replace the current free-text Comparative Years input with structured controls.

Keep:

Period Covered Year
Example:
2025

Add:

Comparative Figures Included?
- No
- Yes

If No:
- store/use no comparative years

If Yes, show:

Number of Comparative Years
- 1
- 2

Then dynamically show:

Comparative Year 1
Comparative Year 2, only when 2 is selected

Suggested defaults:

Period Covered Year = 2025
Comparative Year 1 = 2024
Comparative Year 2 = 2023

Allow the user to edit them.

Validation rules:

- no duplicate years
- comparative year cannot equal the Period Covered Year
- comparative year should be earlier than the Period Covered Year
- maximum 2 comparative years for this prototype

Do not use a manually typed comma-separated field in the UI.

Reuse the existing document metadata/storage format if practical.
Avoid schema redesign unless absolutely necessary.

--------------------------------------------------
2. PASS ALL SELECTED YEARS TO EXTRACTION
--------------------------------------------------

When an AFS is analyzed:

- build the reporting-year list from:
  Period Covered Year
  + selected Comparative Years

Example:

[2025, 2024, 2023]

The existing figure extraction process should attempt extraction for every selected fiscal year supported by its current text rules.

Important:

- do NOT invent missing comparative figures
- do NOT copy the current-year value into another year
- if a year/value is not reliably found, simply do not create that figure row
- preserve the correct fiscal_year on every extracted figure

Do NOT implement advanced table-column OCR in this iteration.

This enhancement should only make the current extraction engine multi-year aware.

--------------------------------------------------
4. FIX YEAR-SPECIFIC SUMMARY LOGIC
--------------------------------------------------

Very important:

Do not aggregate values from different fiscal years together.

Normalized Figure Buckets must be grouped by:

normalized_label + fiscal_year

NOT only normalized_label.

Example:

total_assets | 2025 | ₱1,248,900,000.00
total_assets | 2024 | ₱1,074,500,000.00

These must remain separate values.

Any hero metric such as Current Revenue must use ONLY the Period Covered Year.

Do not accidentally display or sum a comparative-year amount as current revenue.
