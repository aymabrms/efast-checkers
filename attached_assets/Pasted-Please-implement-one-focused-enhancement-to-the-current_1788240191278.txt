Please implement one focused enhancement to the current SEC eFAST Checkers prototype:

NLP-ASSISTED EVIDENCE EXTRACTION V1

IMPORTANT:
- Inspect the existing code first
- Keep this low-risk and low-credit
- Do NOT redesign the UI
- Do NOT add a trained NLP model, LLM, external API, vector database, ML classifier, or background worker
- Do NOT modify GIS, Historical View, Rankings, demo seeding, final reviewer disposition, Multi-Year AFS Support, Computed Confidence weights, Test Upload Management, or OCR behavior except for small compatibility integration
- Preserve the corrected AFS Completeness business rules
- Generate the requested validation MD file
- Stop after this scope

GOAL

Add a lightweight NLP-assisted evidence layer that recognizes common wording variations in AFS text extracted from either:

- PDF Text Layer
- OCR Fallback

The NLP layer should improve evidence recognition while keeping all final validation decisions deterministic and explainable.

--------------------------------------------------
1. VERIFY SPACY AVAILABILITY FIRST
--------------------------------------------------

Check whether spaCy is already available in the Replit environment.

If available:
- use it.

If not:
- add only the minimal spaCy dependency needed for this prototype.

Do NOT download a large pretrained model such as:
- en_core_web_sm
- transformer models

Preferred approach:

spacy.blank("en")
PhraseMatcher
Matcher

If spaCy cannot be installed cleanly without major environment changes:
- stop implementation
- generate the validation MD documenting the blocker.

--------------------------------------------------
2. CREATE ONE SHARED NLP EVIDENCE MODULE
--------------------------------------------------

Create a small reusable module, for example:

nlp_evidence.py

Use:

- spaCy blank English pipeline
- PhraseMatcher for known terminology / aliases
- Matcher where token-order patterns are useful

Do not scatter NLP logic across many page modules.

The module should return deterministic evidence such as:

{
  "concept": "STATEMENT_CASH_FLOWS",
  "matched_text": "Cash Flow Statement",
  "start": ...,
  "end": ...,
  "rule": "phrase_alias"
}

Keep it simple.

4. PRESERVE COMPLETENESS FALSE-POSITIVE SAFEGUARD
--------------------------------------------------

VERY IMPORTANT:

The previously corrected business rule must remain:

REFERENCE TEXT DOES NOT EQUAL ACTUAL COMPONENT PRESENCE.

A page classified as:

Independent Auditor's Report

must NOT satisfy these components merely because its narrative mentions them:

- Financial Position
- Income
- Comprehensive Income
- Changes in Equity
- Cash Flows

The new NLP matcher must respect the same exclusion.

Do NOT reintroduce the previously fixed Auditor's Report false positive.

5. PERIOD / DATE EVIDENCE
--------------------------------------------------

Use lightweight token or deterministic patterns to recognize common reporting-period wording variations.

Examples:

- for the year ended December 31, 2025
- for the fiscal year ended December 31, 2025
- for the year ended 31 December 2025
- as at December 31, 2025
- as of December 31, 2025
- December 31, 2025 and 2024

The NLP layer should return candidate years / date phrases.

Do NOT replace existing Period Covered business rules yet.

Instead:
- provide normalized evidence to the existing period checker.

Example normalized evidence:

{
  "type": "REPORTING_PERIOD",
  "text": "for the year ended 31 December 2025",
  "years": [2025]
}

Multi-Year AFS Support must continue to determine which years are selected/current/comparative.

6. COMPANY-NAME EVIDENCE
--------------------------------------------------
